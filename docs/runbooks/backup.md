# Backup operations

Denyra uses an optional encrypted Restic backup for disaster recovery. The Restic repository must be outside `DENYRA_HOME`; it may be another directory, disk, or mounted remote repository.

Create or mount the repository path, then run:

```sh
export DENYRA_RESTIC_REPOSITORY_PATH=/mnt/denyra-restic
./denyra backup
```

The password comes from the secret generated by `./denyra setup`. The command enables maintenance, waits for active work to drain, and briefly stops Lidarr, Navidrome, SFTPGo, and slskd. Gateway and pipeline databases are copied through SQLite's online backup API.

The encrypted backup includes:

- external config and secrets
- Managed and Unmanaged libraries plus service state
- incoming uploads, including incomplete browser uploads, processing work, and quarantine
- durable upload sessions, unmanaged import intents, catalog check batches, and confirmed migration state in Pipeline SQLite
- consistent Gateway and Pipeline database copies
- a manifest containing the Denyra Git commit and file checksums

Raw downloads, cache, local update snapshots, temporary backup workspaces, the readable credential report, and live Gateway or Pipeline SQLite files are excluded.

After backup, Denyra runs `restic check` and retains 7 daily, 4 weekly, and 12 monthly snapshots. Services restart and maintenance is disabled even if backup fails. A failed run keeps its temporary workspace and prints the path.

Run a restore drill after initial setup and after material database or backup changes. A backup is useful only after its restore path has been checked.
